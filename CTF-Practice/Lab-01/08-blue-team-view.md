# 08 蓝队检测视角与防御建议

作为红队，不仅要会攻击，还要了解防守方是如何发现我们的。以下是从蓝队（应急响应/安全运营）视角，针对本次攻击链各阶段的检测点和防御建议。

## 检测点 1：.git 源码泄露

- **攻击特征**：Web 日志中出现大量对 `/.git/` 目录的请求（如 `GET /.git/config`、`GET /.git/HEAD`），且返回状态码为 200。
- **防御建议**：部署生产环境时，必须删除 `.git` 目录；或在 Nginx/Apache 配置中直接禁止访问 `.git` 路径。

## 检测点 2：后台登录与密码修改

- **攻击特征**：
  - 数据库审计日志中出现异常的 `UPDATE` 语句（如直接修改 `ey_admin` 表的密码字段）。
  - Web 日志中出现针对 `admin_login.php` 的异常登录请求（如短时间内大量失败尝试，随后成功登录）。
- **防御建议**：
  - 修改后台默认入口路径，禁止弱口令。
  - 数据库账号遵循最小权限原则，Web 应用不要使用 `root` 直接连接数据库。
  - 对后台登录接口开启验证码、登录失败锁定策略。

## 检测点 3：文件上传绕过

- **攻击特征**：
  - 上传请求中 `filename` 字段包含 `.phar`、`.phtml`、`.php5` 等非常规后缀。
  - 上传请求的 `Content-Type` 被篡改为 `image/jpeg`，但文件真实内容为 PHP 代码。
- **防御建议**：
  - 使用白名单校验后缀（仅允许 `jpg|png|gif` 等）。
  - 上传后强制重命名文件（如时间戳+随机字符）。
  - 限制上传目录的执行权限，禁止在上传目录内解析 PHP。

## 检测点 4：Redis 提权

- **攻击特征**：
  - Redis 日志中出现 `CONFIG SET dir`、`CONFIG SET dbfilename`、`SAVE` 等危险操作。
  - 系统文件监控告警：`/root/.ssh/authorized_keys` 文件被异常修改。
- **防御建议**：
  - Redis 不以 root 权限运行，使用专用的低权限用户。
  - 设置强密码，禁止 Redis 暴露在公网。
  - 在 Redis 配置文件中禁用或重命名 `CONFIG`、`SAVE` 等危险命令。

## 检测点 5：SUID 程序执行与提权

- **攻击特征**：
  - Web 用户（如 `www-data`）执行了 `find / -perm -4000` 等提权枚举命令。
  - 执行了 `/readflag` 等非常规 SUID 程序。
- **防御建议**：
  - 定期审计系统中的 SUID 文件（`find / -perm -4000`）。
  - 使用 AppArmor、SELinux 等安全模块限制 Web 用户的命令执行权限。
  - 及时更新系统和组件，防止内核漏洞提权。

## 总结：红蓝结合思维

攻击链的每一步在防守方眼里都会留下日志和痕迹。作为安全从业者，掌握攻击思路是为了更好地设计防御策略，发现安全盲区。
