# 03 蓝队检测视角与防御

CTFHub 中的题目大多是真实漏洞的缩影，对应蓝队防御策略如下：

## 1. 信息泄露防御

- **检测点**：Web 日志中对 `.zip`、`.bak`、`.git`、`.svn`、`phpinfo.php` 等敏感路径的访问请求。
- **防御建议**：
  - 部署时删除备份文件、开发测试文件和版本控制目录（`.git`、`.svn`）。
  - 禁止 Web 服务器目录遍历，限制对敏感路径的访问。
  - 在 `php.ini` 中设置 `expose_php = Off`，避免泄露 PHP 版本。

## 2. SQL 注入防御

- **检测点**：Web 日志或 WAF 告警中出现 `UNION`、`SELECT`、`SLEEP`、`UPDATEXML`、`OR 1=1` 等特征。
- **防御建议**：
  - 使用参数化查询，避免拼接 SQL。
  - 部署 WAF，拦截带有 SQL 注入特征的请求。
  - 限制数据库账号权限，Web 应用不应直接使用 `root` 连接数据库。

## 3. 命令注入防御

- **检测点**：Web 日志中出现 `;`、`|`、`&&`、`%0a`、`${IFS}` 等命令连接符特征。
- **防御建议**：
  - 白名单校验输入参数（如仅允许 IP 格式）。
  - 禁用危险函数（`system`、`exec`、`shell_exec`）。
  - 限制 Web 用户的系统命令执行权限。

## 4. 文件上传与文件包含防御

- **检测点**：
  - 上传请求中 `filename` 包含 `.php`、`.phtml`、`.phar`、`.jpg.php` 等异常后缀。
  - 文件包含请求参数中出现 `../`、`php://filter`、`/etc/passwd`。
- **防御建议**：
  - 上传文件重命名（如时间戳+随机字符），限制上传目录执行权限。
  - 文件包含采用精确白名单（`in_array`），设置 `open_basedir`。
  - 关闭 `allow_url_include` 等危险配置。

## 5. SSRF 防御

- **检测点**：服务器异常发起对内网 IP 段（如 `127.0.0.1`、`10.0.0.0/8`、`169.254.169.254`）的请求。
- **防御建议**：
  - 对用户输入的 URL 进行白名单限制。
  - 禁止访问内网 IP 段，禁止使用 `file://`、`gopher://`、`dict://` 等危险协议。
  - 如果业务必须访问外部 URL，使用代理并严格校验目标地址。

## 6. 总结

CTFHub 的题目覆盖了常见的 Web 漏洞场景。作为蓝队，需要建立完善的日志收集和 WAF 告警规则，同时从代码层面对漏洞进行根本性修复（参数化查询、白名单校验、最小权限原则）。
