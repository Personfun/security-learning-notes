# 04 面试问题点与复盘

针对 CTFHub 靶场涉及的细分技能点，整理面试中高频出现的问题及标准回答。

## Q1：CTF 中的“信息泄露”通常有哪些类型？
**A**：常见的信息泄露类型包括：
1. **版本控制泄露**：`.git`、`.svn` 源码泄露。
2. **备份文件泄露**：`www.zip`、`index.php.bak`、`.swp` 文件。
3. **敏感信息泄露**：`phpinfo.php` 泄露环境变量、数据库密码；`robots.txt` 泄露隐藏目录。
4. **目录遍历**：服务器未正确配置，可直接浏览目录列表。
防御方式：部署时删除测试文件、备份文件和版本控制目录；关闭目录遍历；设置 `expose_php = Off`。

## Q2：CTF 中的“报错注入”原理是什么？常用函数有哪些？
**A**：报错注入利用数据库在执行 SQL 时产生的错误信息，将我们想要查询的数据拼接在错误信息中返回。
常用函数：
- MySQL：`updatexml()`、`extractvalue()`、`floor()`。
- 以 `updatexml()` 为例：`1' AND updatexml(1, concat(0x7e, database()), 1) #`。第二个参数如果不符合 XPath 格式，就会报错并把内容显示在错误信息里。
防御方式：关闭数据库详细错误回显，使用参数化查询。

## Q3：命令注入中过滤了空格和关键字，你怎么绕过？
**A**：
1. **过滤空格**：使用 `${IFS}`、`%09`（Tab）、`<` 或 `$IFS$9` 代替空格。
2. **过滤关键字**：使用变量拼接（如 `a=c; b=at; $a$b /flag`）、Base64 编码（`echo Y2F0... | base64 -d | bash`）、反斜杠转义（`c\at /flag`）。
3. **无回显盲注**：利用 DNSLog 外带数据，或者写入文件后再通过 Web 访问。
核心思路：黑名单永远有遗漏，尽量寻找没被过滤的字符或利用编码、变量拼接绕过。

## Q4：文件包含漏洞如何配合 PHP 伪协议利用？
**A**：
1. **读源码**：`php://filter/convert.base64-encode/resource=index.php`。
2. **执行代码**：如果 `allow_url_include = On`，可以使用 `data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWydjbWQnXSk7Pz4=` 或者 `php://input` 直接 POST PHP 代码执行。
3. **包含日志**：将 PHP 代码写入 User-Agent，然后通过文件包含包含 Apache 访问日志（`/var/log/apache2/access.log`），实现 Getshell。
防御方式：使用精确白名单，设置 `open_basedir`，关闭 `allow_url_include`。

## Q5：SSRF 漏洞常见的利用协议有哪些？如何防御？
**A**：
常见协议：
- `http://`：探测内网 Web 服务。
- `file://`：读取服务器本地文件（如 `file:///etc/passwd`）。
- `gopher://`：构造任意 TCP 数据包，攻击内网 Redis、MySQL、FastCGI 等服务。
- `dict://`：探测内网服务端口。
防御方式：
1. 对用户输入的 URL 进行白名单限制。
2. 禁止访问内网 IP 段（如 `127.0.0.1`、`10.0.0.0/8`、`169.254.169.254`）。
3. 禁止使用 `file://`、`gopher://` 等危险协议。

## Q6：如果目标只能盲注（无回显），你怎么办？
**A**：
1. **布尔盲注**：利用 `AND 1=1` 和 `AND 1=2` 观察页面差异，逐步推断数据。
2. **时间盲注**：利用 `SLEEP(5)` 观察响应时间差来推断数据。
3. **DNSLog 外带**：利用数据库的 `load_file()` 或者 `xp_dirtree` 函数，向外部 DNSLog 平台发起请求，把查询结果带出来（无需回显，适合实战）。

## 总结：CTF 带给我的收获

CTF 刷题让我把各个零散的知识点串联了起来。**遇到题目时，先做信息收集，判断题型，然后尝试最直接的 Payload，不断调整绕过策略。** 这种“快速定位漏洞点 → 构造利用链 → 绕过防御”的思维，在真实渗透测试和面试中都非常有价值。
