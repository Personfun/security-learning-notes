# 04 面试问题点与复盘

针对 DVWA 靶场涉及的漏洞类型，整理面试中高频出现的问题及标准回答。

## Q1：SQL 注入的防御方式有哪些？
**A**：最有效的是**参数化查询（Prepared Statements）**，其次是输入验证（白名单）、使用 ORM 框架、限制数据库账号权限、开启 WAF 拦截。在代码审计中，看到直接拼接 SQL 字符串的代码，就要警惕注入风险。Impossible 难度采用的就是参数化查询，所以彻底防住了 SQL 注入。

## Q2：文件上传如何绕过白名单校验？
**A**：白名单校验很难直接绕过，通常需要配合其他漏洞：
1. 利用文件包含漏洞（LFI）执行图片马。
2. 利用服务器解析漏洞（如 Apache 多后缀解析、Nginx 解析漏洞）。
3. 寻找其他隐藏的上传点（如未纳入安全测试的接口）。

## Q3：文件包含 Medium 难度中，`str_replace` 为什么会失效？
**A**：`str_replace` 是“删除”匹配的字符串，而不是“拼接”。我们可以通过双写（`hthttp://tp://`）或者大小写混合来绕过简单的字符替换。这说明黑名单防御永远是脆弱的，只有白名单才是可靠的。

## Q4：XSS 的三种类型是什么？如何防御？
**A**：反射型（URL 参数直接回显）、存储型（存入数据库后其他用户访问触发）、DOM 型（纯前端 JS 处理不当）。
防御核心：输出转义（`htmlspecialchars`）+ HttpOnly Cookie + CSP（内容安全策略）。

## Q5：你如何理解“黑名单”和“白名单”在安全防御中的区别？
**A**：黑名单是“禁止已知的坏东西”，永远无法穷举，容易被绕过（如命令注入中用 `%0a` 绕过 `&&` 和 `;`）。白名单是“只允许已知的好东西”，安全强度更高。比如 Impossible 级别的文件包含采用精确数组匹配，基本无法绕过；Impossible 级别的命令注入采用 `is_numeric` 白名单，彻底防住。

## Q6：命令注入 High 难度中，过滤了空格和管道符，你怎么绕过？
**A**：我利用了换行符 `%0a`。在 URL 中传入 `127.0.0.1%0aid`，换行符会被当作命令分隔符，从而执行 `id`。这说明黑名单过滤不完整，永远有遗漏的字符（如换行符、Tab、反引号等）。

## Q7：如果目标服务器部署了 WAF，你的 SQL 注入怎么绕过？
**A**：可以尝试以下方式：
1. 大小写混合（`SeLeCt`）。
2. 内联注释（`/*!SELECT*/`）。
3. 双写关键字（`SELSELECTECT`）。
4. 等价替换（`OR 1=1` 换成 `OR 2>1`）。
5. 编码绕过（URL 编码、十六进制编码）。
6. 分块传输（Chunked Transfer）。
最终核心还是需要手工测试，找到 WAF 规则覆盖不到的地方。

## 总结：DVWA 带给我的收获

DVWA 让我从“会打”升级到了“懂原理、懂防御”。通过对比 Low、Medium、High、Impossible 四个难度，我清楚地看到了安全防御的演进：从无防护，到黑名单过滤，再到白名单和参数化查询。**在真实工作中，只要条件允许，就必须使用白名单和安全框架，绝不能依赖黑名单。**
