# 03 蓝队检测视角与防御

针对 DVWA 中的各类漏洞，蓝队可以通过代码层修复和日志监控进行有效防御。本笔记从攻击链出发，逐一分析检测点和防御策略。

## 1. SQL 注入防御

- **代码层**：
  - 使用 PDO 或 MySQLi 的预处理语句（Prepared Statements），彻底分离代码和数据。
  - 严格校验输入参数类型（如 `is_numeric()`），限制输入格式。
- **日志层**：
  - 监控 Web 日志中的 `UNION`、`SELECT`、`OR 1=1` 等敏感关键字。
  - 部署 WAF（如 ModSecurity）规则，拦截常见的 SQL 注入特征。

## 2. 命令注入防御

- **代码层**：
  - 避免直接调用 `system()`、`exec()`、`shell_exec()` 等危险函数。
  - 如果必须使用，严格使用白名单校验参数（如仅允许 IP 格式）。
- **日志层**：
  - 监控 Web 进程异常调用的子进程（如 `bash`、`whoami`、`cat`、`id`）。
  - 使用 HIDS（如 Wazuh）监控 `web` 用户的异常命令执行行为。

## 3. 文件包含防御

- **代码层**：
  - 使用 `in_array()` 精确白名单匹配，禁止用户控制包含路径。
  - 对用户输入进行严格的路径检查，过滤 `../`、`php://` 等特殊字符。
- **配置层**：
  - 在 `php.ini` 中设置 `open_basedir` 限制 PHP 访问的目录范围。
  - 关闭不必要的 PHP 危险配置（如 `allow_url_include = Off`）。
- **日志层**：
  - 监控请求参数中出现 `../`、`php://filter`、`/etc/passwd` 等特征。

## 4. 文件上传防御

- **代码层**：
  - 采用白名单校验后缀（仅允许 `jpg|png|gif`）。
  - 上传后强制重命名文件（如时间戳+随机字符）。
  - 限制上传目录的执行权限（禁止解析 PHP）。
  - 校验文件头（Magic Bytes），而不仅是 Content-Type 或后缀。
- **日志层**：
  - 监控包含 `.php`、`.phtml`、`.phar` 等后缀的上传请求。
  - 监控上传目录中异常生成的可执行文件。

## 5. XSS 防御

- **代码层**：
  - 输入过滤（`strip_tags`）与输出转义（`htmlspecialchars`）。
  - 设置 `Set-Cookie: HttpOnly` 防止 Cookie 被窃取。
  - 部署 CSP（内容安全策略），限制脚本执行来源。
- **日志层**：
  - 监控请求参数中是否包含 `<script>`、`onerror=`、`javascript:` 等标签。

## 6. 总结：黑名单 vs 白名单

| 防御方式 | 代表做法 | 安全性 |
|:---|:---|:---|
| 黑名单 | 过滤 `select`、`union`、`../`、`php` | 低，容易被绕过（如 `%0a`、双写、大小写） |
| 白名单 | 只允许已知的安全值（如 `in_array` 精确匹配） | 高，基本无法绕过 |

**结论**：黑名单是“禁止已知的坏东西”，永远无法穷举；白名单是“只允许已知的好东西”，是安全的根本。
